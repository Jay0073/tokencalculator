Three layouts that are not a table

Each one starts from a different question rather than a different shape. Drag the workload controls and watch what each layout does: that behaviour is the point of the design, not the styling. All three use the live 35-model catalogue and real arithmetic.

Provider is the wrong top-level grouping. Nobody decides "I want an Anthropic model" before knowing the price. They decide what they are willing to spend. So the shelves are price bands and the provider drops to a coloured dot. Drag the output slider and watch models jump between shelves - that reshuffle is the insight the current design hides, because output-heavy work reorders the market completely. Tap any model to open it in place.

Reverse the calculation. A price per call is an abstraction; nobody has an intuition for $0.000124. The question people actually ask is "I have this much a month, how far does it go?" So the input is a budget and the answer is a number of requests. It makes a 20x price gap feel like what it is: 40,000 requests against 800,000.

$ per month, on this workload

Show the bill, then let them fix one line. A receipt is a format everyone can already read, and it makes the input-versus-output split obvious without a legend. Comparison happens by substitution rather than scanning: pick an alternative, the receipt re-renders and the old total stays struck through so the change is legible.
